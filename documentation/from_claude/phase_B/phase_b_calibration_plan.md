## Executive Summary

Phase B adds two calibration layers to PROLACTIN:

1. **Frequency response correction** — FIR inverse filter convolution to flatten DT250 response
2. **Absolute SPL mapping** — dB FS → dB SPL conversion so paradigm levels are physically meaningful

Both are needed for all 11 paradigms. The code-only steps (B1a, B2a, B2b) can proceed immediately. Measurement steps use the lab's B&K 4153 artificial ear + RME UFX II.

**Design goal:** All thresholds and levels exposed to the user should be in dB — either relative dB or absolute dB SPL, as appropriate per paradigm.

## Current State: What Needs Fixing

### The `db_spl_to_amplitude()` problem

IFMC and TMC each have their own copy of this method doing `db_spl / 100.0` — a linear mapping that is physically meaningless. 0 dB SPL maps to silence, 50 dB SPL maps to amplitude 0.5, 100 dB SPL maps to 1.0. This bears no relationship to actual sound pressure.

PTA works directly in amplitude (0–1) and uses `db2amp()` / `amp2db()` for relative dB steps. It never claims to operate in dB SPL — it just finds the threshold in "whatever units the system produces."

The other paradigms (AM, FM, GAP, DLI) similarly work in relative amplitude. ILD and ITD build their own stereo signals and use relative levels.

**Bottom line:** Nothing in the current system produces calibrated SPL. Post-calibration, the goal is for all user-facing values to be in dB (relative or absolute SPL as appropriate), with `db2amp()` / `amp2db()` and `CalibrationManager.spl_to_amplitude()` / `amplitude_to_spl()` handling all conversions internally.

### The signal chain integration gap

In `play_trial()`, each event is generated by EventGen → immediately wrapped in a PsychoPy `Sound` object → scheduled for playback. There's no intermediate step where raw numpy samples can be intercepted for FIR convolution. Once samples are inside a `Sound` object, they're baked in — PsychoPy/PTB has no real-time DSP chain to hook into.

The cleanest approach is a **single gateway method** on CalibrationManager that all code paths funnel through just before creating Sound objects. This avoids patching five separate locations and gives us one point of control for the entire calibration pipeline.

ILD and ITD bypass TrialPlayer entirely — they construct their own stereo numpy arrays and wrap them in `Sound` objects directly. These also call the gateway method.

---

## Architecture Decision: FIR Convolution vs Per-Frequency Lookup

The MultiThreshold MATLAB approach uses a **per-frequency dB attenuation lookup table** — measure the deviation at each test frequency, store correction values, apply as gain adjustments.

PROLACTIN uses **FIR inverse filter convolution** instead. This is the better choice because:

- Several paradigms use **broadband stimuli** (white noise in GAP, DLI, ILD, ITD) where per-frequency correction doesn't apply
- FIR handles the **full spectrum continuously**, including masker tones at arbitrary frequencies (IFMC masker ratios) and future use with voice/sample playback
- It's **one mechanism** for all signal types rather than separate code paths for tones vs broadband
- With minimum-phase FIR, **added latency is negligible** (~5ms for a 256-tap filter at 48kHz)
- **Extensible** to other transducers — swap in a different IR WAV file per headphone profile

### B1a — CalibrationManager class (code-only, no hardware)

**New file:** `utils/calibration.py`

```

├── load_config()                            # parse calibration_config.json

├── spl_to_amplitude(db_spl)                 # calibrated dB SPL → (amp_L, amp_R) tuple
├── amplitude_to_spl(amplitude, channel)     # inverse for display/logging (specify 'left' or 'right')
├── max_spl                                  # property: hard safety ceiling
├── is_calibrated                            # property: True if real data loaded
├── active_profile                           # property: current headphone profile name
└── summary()                                # print calibration state
```

**The gateway method — `prepare_sound()`:**

This is the single point where all audio funnels through before playback. It handles:
1. Mono → stereo conversion (respecting pan if provided)
2. FIR inverse filter convolution (per-channel)
3. Safety clipping check (warn if amplitude exceeds 1.0 after convolution)
4. Wrapping in PsychoPy `Sound` object

```python
def prepare_sound(self, samples, fs, pan=None):
    """
    Gateway: apply calibration and return a PsychoPy Sound object.
    
    Args:
        samples: 1D numpy array (mono) or 2D (n_samples, 2) stereo
        fs: sample rate
        pan: None/0=diotic, <0=left only, >0=right only
    
    Returns:
        psychopy.sound.Sound object ready for playback
    """
    # 1. Ensure stereo
    if samples.ndim == 1:
        if pan is not None and pan < 0:
            stereo = np.column_stack([samples, np.zeros_like(samples)])
        elif pan is not None and pan > 0:
            stereo = np.column_stack([np.zeros_like(samples), samples])
        else:
            stereo = np.column_stack([samples, samples])
    else:
        stereo = samples.copy()
    
    # 2. Apply inverse filter (per-channel)
    # requires: from scipy.signal import fftconvolve
    #
    # !!! IMPORTANT: the mode='same' snippet below is OBSOLETE and WRONG.
    # !!! See "Convolution mode correction (2026-04-30)" addendum at the
    # !!! end of this document for the rationale and the correct
    # !!! mode='full' implementation. The production code in
    # !!! utils/calibration.py uses mode='full' with full-length output.
    if self._ir_left is not None:
        stereo[:, 0] = fftconvolve(stereo[:, 0], self._ir_left, mode='same')
    if self._ir_right is not None:
        stereo[:, 1] = fftconvolve(stereo[:, 1], self._ir_right, mode='same')
    
    # 3. Safety check
    peak = np.max(np.abs(stereo))
    if peak > 1.0:
        warnings.warn(f"Calibration clipping: peak={peak:.3f}. Clamping to 1.0.")
        stereo = np.clip(stereo, -1.0, 1.0)
    
    # 4. Wrap in Sound
    duration = stereo.shape[0] / fs
    return sound.Sound(value=stereo, sampleRate=fs, stereo=True,
                       secs=duration, hamming=False)
```

**Why a gateway rather than inline convolution:**
- Single integration point — TrialPlayer, ILD, ITD, and any future code all call this one method
- Pan logic consolidates here instead of being duplicated in `play_trial()`
- Easy to extend later (e.g., add limiter, add metering, add latency compensation)
- Clean separation: EventGen creates samples, CalibrationManager prepares them for playback

**Key design decisions:**

1. **Optional dependency** — CalibrationManager is passed into TrialPlayer at construction. If None, TrialPlayer falls back to its current behavior (raw mono Sound objects). No paradigm code breaks.

2. **Graceful degradation** — if config is missing or has `null` values:
   - `prepare_sound()` still works (just skips convolution — flat response is still usable for relative measurements)
   - `spl_to_amplitude()` raises an error if calibration data is null (no silent fallback — uncalibrated SPL values are meaningless)
   - `is_calibrated` property returns False
   - Warning printed once at startup (not per trial)

3. **Per-channel IR storage** — separate left/right WAVs. For diotic presentation when pan=None, both channels get their respective corrections.

4. **Resampling guard** — if IR sample rate ≠ system sample rate (48kHz), resample via `scipy.signal.resample_poly`. Warn if this happens.

5. **Safety ceiling** — `max_spl` hard limit (default 105 dB SPL, configurable per profile). `spl_to_amplitude()` refuses to return amplitudes above the ceiling. This protects against bugs producing dangerously loud output, especially important for LDL.

6. **Multi-profile support** — config file supports named profiles. Default profile loaded at startup; profile can be switched via setup dialog or test script parameter. Structure designed so adding a new headphone = adding a new JSON profile + IR WAVs.

**Config file structure (`calibration/calibration_config.json`):**

```json

```

**Profile naming convention:** `{headphone}_{interface}` — so if you later measure the DT250 through a different interface, or different headphones through the UFX II, each combo gets its own profile.

**The `retspl` field:** Reserved for future dB HL conversion. RETSPL stands for **Reference Equivalent Threshold Sound Pressure Level** — it's the SPL at which 0 dB HL (hearing level) is defined for each frequency for a specific transducer + coupler combination. When populated, this field will be a frequency-indexed lookup table (e.g., `{"1000": 7.0, "4000": 9.0, ...}`) and the conversion is simply `dB_HL = measured_dB_SPL - RETSPL(frequency)`. This is a methodology decision for you and your colleagues — the code just needs to support an optional offset table. The B&K 4153 being an IEC 60318-3 standard coupler means published RETSPL values *may* apply, but would need verification for the DT250 specifically (it's not a standard audiometric transducer). Options: (a) measure RETSPL empirically with normal-hearing listeners, (b) use published values for similar circumaural phones and note the approximation, (c) report PTA thresholds in dB SPL only.

### B2a — spl_to_amplitude() centralization (code-only)

**The core conversion:**

```python
def spl_to_amplitude(self, db_spl):
    """
    Convert dB SPL to digital amplitude using measured calibration.
    
    Returns per-channel amplitudes because L/R ears have different
    measured SPL offsets. For diotic presentation, both values are
    applied to their respective channels so that the requested dB SPL
    is achieved at EACH ear independently.
    
    Method: We measured that amplitude=ref_amp produces ref_spl dB SPL
    at 1 kHz. For any target SPL:
    
        amplitude = ref_amp * 10^((target_spl - ref_spl) / 20)
    
    Args:
        db_spl: desired sound pressure level in dB SPL
    
    Returns:
        (amp_left, amp_right) tuple
    
    Raises:
        CalibrationError if SPL calibration data is null
    """
    spl_L = self.config["spl_calibration"]["measured_spl_left"]
    spl_R = self.config["spl_calibration"]["measured_spl_right"]
    if spl_L is None or spl_R is None:
        raise CalibrationError(
            "SPL calibration data not set. Run calibrate_spl.py first.")
    
    if db_spl > self.max_spl:
        warnings.warn(f"Requested {db_spl} dB SPL exceeds safety limit "
                       f"of {self.max_spl} dB SPL. Clamping.")
        db_spl = self.max_spl
    
    ref_amp = self.config["spl_calibration"]["reference_amplitude"]
    amp_L = ref_amp * 10 ** ((db_spl - spl_L) / 20.0)
    amp_R = ref_amp * 10 ** ((db_spl - spl_R) / 20.0)
    return amp_L, amp_R

def amplitude_to_spl(self, amplitude, channel):
    """
    Inverse of spl_to_amplitude — for display/logging.
    
    Args:
        amplitude: digital amplitude value
        channel: 'left' or 'right' (must be explicit)
    """
    ref_amp = self.config["spl_calibration"]["reference_amplitude"]
    if channel == 'left':
        ref_spl = self.config["spl_calibration"]["measured_spl_left"]
    else:
        ref_spl = self.config["spl_calibration"]["measured_spl_right"]
    return ref_spl + 20 * np.log10(amplitude / ref_amp)
```

**What changes in paradigm code:**
- Delete `db_spl_to_amplitude()` from `paradigm_ifmc.py` and `paradigm_tmc.py`
- Both paradigms call `self.calibration.spl_to_amplitude()` instead
- `self.calibration` is set by the base class from the injected CalibrationManager

**Broader dB migration (all paradigms, phased):**

The end goal is that all user-facing values are in dB. This happens in two waves:

**Wave 1 (Phase B scope) — IFMC + TMC:**
Already use "dB SPL" internally (with the fake linear mapping). Wire them up to CalibrationManager — the inner variable configs and operator display labels stay the same, only the conversion function changes.

**Wave 2 (post-Phase B) — remaining paradigms:**

| Paradigm | Current inner var | Target inner var | Conversion |
|----------|------------------|-----------------|------------|
| PTA | amplitude (0-1) | dB SPL (or dB HL) | spl_to_amplitude() |
| LDL | amplitude (0-1) | dB SPL | spl_to_amplitude() |
| AM | modulation depth (0-1) | modulation depth in dB (20*log10) | db2amp() |
| FM | mod_ind (%) | mod_ind (%) — already a dB-like scale | no change needed |
| GAP | gap duration (s) | gap duration (s) — not a level | no change needed |
| DLI | amplitude step (relative) | dB step (relative) | db2amp() |
| ILD | ILD in dB | already in dB | no change needed |
| ITD | ITD in ms | not a level — already fine | no change needed |

For PTA, AM, GAP, DLI: the carrier/reference level also needs calibration (presented at a known dB SPL). This is a config parameter, not an adaptive variable — add a `reference_level_spl` field to each paradigm's params that CalibrationManager converts.

### B2b — TrialPlayer integration (code-only)

**Changes to `play_trial()`:**

The current approach: each event is generated, pan is optionally applied, then each event is scheduled as a separate `Sound` object with PTB timing.

The new approach: each event is generated as a raw numpy array, then passed through `calibration.prepare_sound()` which handles stereo + convolution + Sound wrapping.

```python
def play_trial(self):
    wave_type = self.vec_expand(self.wave_type, self.num_events)
    sound_list = [None] * self.num_events
    
    for i in range(self.num_events):
        # Generate raw samples (always get wav_dict for numpy access)
        if wave_type[i] == "sin":
            _, wav_dict = self.eg.sin(..., return_dict=True)
        elif wave_type[i] == "fm":
            _, wav_dict = self.eg.fm(..., return_dict=True)
        # ... etc
        
        mono = wav_dict["values"]
        
        # Gateway: calibration + stereo + Sound wrapping
        if self.calibration is not None:
            sound_list[i] = self.calibration.prepare_sound(
                mono, self.fs, pan=self.pan)
        else:
            # Fallback: current behavior (no calibration)
            if self.pan is not None and self.pan != 0:
                if self.pan < 0:
                    stereo = np.column_stack([mono, np.zeros_like(mono)])
                else:
                    stereo = np.column_stack([np.zeros_like(mono), mono])
                sound_list[i] = Sound(value=stereo, sampleRate=self.fs,
                                      stereo=True, secs=self.durations[i],
                                      hamming=False)
            else:
                sound_list[i] = Sound(value=mono, sampleRate=self.fs,
                                      stereo=True, secs=self.durations[i],
                                      hamming=False)
    
    # ... rest of scheduling/playback unchanged
```

**sample_accurate path:** The concatenated `tmp_snd` array also goes through `prepare_sound()` before wrapping.

**Background sound:** If `bg['play_bg']` is True, the noise also goes through `prepare_sound()`.

### B3 — Measurement: SPL Offset (requires hardware)

**What you're measuring:** "When my system outputs amplitude X at 1 kHz, what SPL does the DT250 produce on the B&K 4153?"

**Procedure:**

1. **Verify calibrator chain:** Connect pistonphone to B&K 4153 mic. Confirm reading of 94 dB SPL at 1 kHz. This establishes the absolute reference.

2. **Lock interface gain:** In RME TotalMix, set headphone output to a fixed level. Note the exact gain setting. **Lock it** (RME TotalMix supports this). Document: e.g., "HP out = -10 dBFS ref, locked."

3. **Generate reference tone:** Play 1 kHz sine at a moderate digital amplitude — suggest `amp = 0.1` (approximately -20 dB FS). Low enough to avoid distortion, high enough for reliable measurement on the mic.

4. **Measure left channel:** Route signal to left channel only. Place left DT250 ear on coupler. Read SPL. Record: e.g., "amp=0.1 at 1 kHz on left = 72.3 dB SPL"

5. **Measure right channel:** Same procedure, right ear. Record value.

6. **Linearity verification:** Change amplitude to 0.05 (approximately -26 dB FS). Measured SPL should drop by ~6 dB. If it doesn't, something is wrong in the signal chain. Also try amp=0.2 — should be ~6 dB higher than the 0.1 measurement.

7. **Write values to `calibration_config.json`.**

**Build a helper script (`calibrate_spl.py`):**
- Generates and plays reference tones at specified amplitudes/frequencies
- Prompts operator to enter measured SPL readings
- Computes and validates the calibration curve (checks linearity)
- Writes results to config file

### B4 — Measurement: Frequency Response + IR Generation (requires hardware)

**What you're measuring:** The DT250's frequency response through the complete signal chain (RME UFX II → DT250 → B&K 4153 → mic → RME UFX II input).

**Procedure (REW):**

1. **Connect measurement loop:** RME HP output → DT250 on coupler → B&K mic → RME line/mic input. Set REW I/O to use the RME.

2. **Configure REW:** Sample rate = 48 kHz. Output level = same locked level as B3. Verify levels aren't clipping in either direction.

3. **Measure left ear:** Route output to left channel only. Run log swept sine. Save measurement.

4. **Measure right ear:** Same, right channel.

5. **Inspect frequency response:** Typical DT250 characteristics: some bass roll-off below ~80 Hz, a presence bump around 3-4 kHz, treble irregularities above 8 kHz. The B&K 4153 coupler has its own response characteristics at high frequencies — this is expected and the inverse filter accounts for it.

6. **Apply 1/6 octave smoothing** to each measurement BEFORE inversion. This limits the correction to the broad headphone response shape and prevents the inverse from chasing narrow artifacts that vary with repositioning.

7. **Generate inverse filter (verified workflow):**
   - **Invert:** All SPL → Trace Arithmetic → **1/A** on the smoothed measurement, with frequency limits 100-10k Hz, max gain 20 dB, exclude notches OFF (produces hard discontinuities when ON), auto target level
   - **Convert to minimum-phase:** Select the 1/A result → All SPL → Measurement actions → **"Minimum phase version"** → Generate and close. This adds a min phase trace (gray line) to the existing 1/A measurement tab (does NOT create a separate tab).
   - **Export:** Select the 1/A tab → File → Export impulse response as WAV → **"Export min phase version of IR"**, 32-bit Float, Mono, Normalize ON, Apply IR Window OFF, Place t=0 at sample index **256**, Export sample count **4k**, 48 kHz
   - See `rew_inverse_filter_instructions.md` for the full verified step-by-step with screenshots and rationale for each setting

8. **Verify in REW:** All SPL → Trace Arithmetic → original measurement * 1/A inverse → result should be flat (+/- 2 dB across 100-10k Hz)

9. **Export left and right inverse IRs** as separate mono WAV files into `calibration/` folder.

**On the target range — room to experiment:**
100 Hz - 10 kHz is the conservative starting point. Worth generating additional filters at:
- 50 Hz - 12 kHz (wider, for paradigms that use low-frequency tones or broadband noise)
- 200 Hz - 8 kHz (narrow, audiometric range only — safest, least boost needed)
Store all variants as separate WAV files; switching between them is just a config change.

**Filter length:** 4096 samples at 48kHz (~85ms). The IR decays within ~100 samples of the peak (at sample 256). The remaining samples are silence. 4096 is a convenient power-of-2 for FFT-based convolution.

**Minimum-phase conversion — why it's necessary:**
The 1/A inversion in REW produces acausal impulse responses (per REW docs: "the result is typically not causal"). The raw "measured" IR has a symmetric peak with energy on both sides — unusable for convolution. The min phase version reconstructs a causal IR with the same magnitude response. You must generate the min phase version via Measurement actions before the export dialog can access it.

### B6 — Verification (requires hardware)

After calibration data is loaded:

1. **Frequency response check:** Play white noise through calibrated system → measure on coupler → response should be flat (+/- 2 dB across 100 Hz - 10 kHz)

2. **Level accuracy check:** Play 1 kHz tone at requested dB SPL values (e.g. 40, 60, 80 dB SPL) via `spl_to_amplitude()` → measure on coupler → should match requested level (+/- 1 dB)

3. **Multi-frequency level check:** Play tones at 250, 500, 1k, 2k, 4k, 8k Hz at same dB SPL → measure → should be equal (+/- 2 dB, demonstrating that inverse filter + SPL calibration compose correctly)

4. **Clipping check:** Request maximum expected level (105 dB SPL) → verify no digital clipping (amplitude stays at or below 1.0) and no audible distortion

5. **Safety check:** Verify `spl_to_amplitude()` refuses values above max_spl ceiling and logs a warning

6. **Compare filter variants:** If multiple IR files were generated (different target ranges / tap counts), run checks 1-3 with each and compare

**Build a verification script (`verify_calibration.py`):** Automates steps 1-5 by generating test signals, prompting operator to record measurements, and reporting pass/fail against tolerances.

### Convolution mode correction

The original snippet (line ~131 of this doc) used `mode='same'` for the
per-channel `fftconvolve`. Empirical testing on a 200ms 1kHz tone with
5ms Hann fade-in/out + a realistic min-phase IR (4096 taps, peak at sample
256) revealed that `mode='same'` is wrong for our use case in two ways:

1. **Onset click.** `mode='same'` skips `(M-1)/2 = 2047` samples from the
   start of the full convolution, which is precisely where the 5 ms
   fade-in lives. Output[0] = 0.73 (full steady-state amplitude) despite
   input[0] = 0. Audible click at every event onset.

2. **Tail obliteration.** The corresponding samples skipped from the end
   of the full convolution include the entire fade-out region. Last 85 ms
   of output goes to ~0, cutting the stimulus off early.

Two alternatives were considered:

- `mode='full'[:N]` (causal trim): preserves fade-in correctly, but the
  fade-out region of the input maps to samples [N, N+M-1] of the full
  convolution due to the IR's group delay. Trimming to N discards them
  -> output ends abruptly at amplitude 0.29 instead of decaying to zero
  -> **end click**.
- `mode='full'` (keep all N+M-1 samples): preserves fade-in AND fade-out;
  ringout decays smoothly to zero at the end. The extra ~85 ms of digital
  output is the **anti-ringing** signal that cancels the headphone's own
  post-stimulus acoustic ringing at the eardrum. This is the physically
  correct answer.

**Decision:** use `mode='full'` and keep the full N+M-1 sample output.

Empirical sanity check (gap detection):

| Metric              | Reference (ideal) | Uncalibrated headphone | Calibrated (mode=full) |
|---------------------|-------------------|------------------------|------------------------|
| Rise time (10->90%) | 1.19 ms           | 1.15 ms                | 1.15 ms                |
| 2 ms gap depth      | -52 dB            | -30 dB                 | -62 dB                 |

The inverse filter does NOT smear the signal -- it produces sharper gaps
than uncalibrated playback because it cancels the headphone's natural
2 kHz resonance ringing. Min-phase FIRs concentrate energy at the start
of the impulse response, so onset/offset transitions are preserved.

The PsychoPy/PTB scheduler handles the longer buffer transparently
(`prepare_sound()` computes `secs = stereo.shape[0] / fs` from the post-FIR
length). For paradigms that bypass TrialPlayer (ILD, ITD), `execute_trial`
adds `cm.ringout_seconds` to the playback wait. TrialPlayer's existing
`+ 0.1s` end-of-trial slack covers everything via the per-event Sound
playback model.

### TrialPlayer: sample_accurate uniform-gain relaxation

GAP requires `sample_accurate=True` for sub-ms gap precision. The original
`_normalize_per_channel_gain` rejected ALL `per_channel_gain` in
`sample_accurate=True` mode, which would have blocked GAP migration.

Mathematical reasoning: a *uniform* `(gain_L, gain_R)` applied to a
concatenated buffer is equivalent to applying it to each event before
concatenation (gain commutes with concatenation). Per-event-different
gains, in contrast, would create step discontinuities at event boundaries
that ring through the FIR convolution — those remain rejected.

Implementation: `_normalize_per_channel_gain` first expands the input to
a per-event list, then in `sample_accurate=True` mode validates that all
non-None entries are equal and that None is not mixed with tuples.
Rejection cases now have clearer error messages explaining the FIR-
ringing rationale and pointing to `sample_accurate=False` as the
alternative for per-event-different gains.

The playback path takes `pcg_list[0]` (uniform tuple, or None) and passes
it to `prepare_sound`'s `per_channel_gain` arg.

### TrialPlayer: ringout-aware `core.wait`

Previously `play_trial`'s `core.wait` used a flat `+ 0.1s` end-of-trial
slack. With current 4096-tap @ 48 kHz IRs (~85 ms ringout), this fit
within the 0.1s slack, so nothing was broken in practice — but the
margin would disappear if IR length grew. The slack also wasn't
mathematically tied to the actual ringout.

New formulation: `core.wait(... + ringout + 0.1)`, where `ringout =
self.calibration.ringout_seconds if self.calibration is not None else 0.0`.
Behavior unchanged in uncalibrated mode (`ringout = 0.0`); calibrated
paradigms now wait an extra ~85 ms per trial.

This fixes the latent ringout issue across all calibrated TrialPlayer
paradigms (PTA, AM, FM, DLI, GAP, IFMC, TMC, ILD). ITD keeps its existing
manual `time.sleep(... + ringout_pad + 0.1)` since it bypasses TrialPlayer.

### ILD: per-ear correctness fix + bypass refactor

Two improvements to ILD this session, beyond the basic SPL migration:

**(1) Per-ear correctness fix.** Pre-migration ILD baked the L/R amplitude
asymmetry directly into the stereo array (`amp_left * mono`,
`amp_right * mono`). This:
- Lost per-ear headphone sensitivity correction (the very thing
  CalibrationManager exists to provide).
- Mixed the ILD ratio with sensitivity correction in a single linear-
  amplitude factor.

The fix builds identical mono in both stereo channels at unit amplitude,
and computes per-ear amplitudes via two `spl_to_amplitude()` calls (one
per per-ear SPL target, taking only the channel-appropriate value from
each). This cleanly separates:
- (a) ILD ratio = pure dB-space arithmetic, independent of headphones
- (b) Per-ear sensitivity correction = absorbed into `per_channel_gain`

Verified offline: with hypothetical 0.5 dB L/R sensitivity asymmetry,
the new code produces exactly 65.0/55.0 dB SPL at the eardrum for a
requested 10 dB ILD at 60 dB SPL ref; old code produced 9.5 dB ILD.

**(2) Refactor: ILD no longer bypasses TrialPlayer.** The original bypass
existed because per-channel amplitude control required direct stereo
construction. With per-ear scaling now living entirely in
`per_channel_gain`, ILD reduces to the standard PTA/AM/FM pattern:

```python
self.tp.new_trial(
    wave_type="sin", durations=self.tone_dur, fc=fc,
    amp=1.0, pan=0,
    per_channel_gain=(amp_L, amp_R),
    fade_time=self.fade_time, sample_accurate=False,
    verbose=False,
)
```

Removed: `execute_trial` override, `play_demo_trial` override, manual
mono/fade/stereo construction, direct `prepare_sound` call,
`self.ild_sound` attribute, `self.fs = 48000` setting, and three imports
(`psychopy.sound`, `time`, `TrialPlayer`). Net ~50 fewer lines of
override/manual-construction logic.

ITD keeps its bypass-TrialPlayer pattern because per-channel **timing**
offsets (one ear receives a delayed signal) are not a TrialPlayer concept.

### Per-ear correction pattern (cross-paradigm)

All Wave-2 paradigms now use the same per-ear-correct pattern:

- **Both ears at same SPL** (PTA, LDL, AM, FM, GAP, ITD): single

- **Per-ear-different SPL targets** (ILD): two `spl_to_amplitude()` calls,

- **Per-event-different SPL targets** (DLI): per-event-list of

### Noise SPL bias documentation

GAP and ITD use noise stimuli. White noise generated as
`np.random.uniform(-1, 1)` (or `tanh`-limited Gaussian for GAP) has
~1.3 dB lower acoustic RMS than a sine wave at the same calibrated peak
amplitude. The bias is documented in the CSV header metadata:
- GAP: `noise_level_acoustic_bias_db: -1.3`
- ITD: `ref_level_acoustic_bias_db_white_noise: -1.3`

Sine-only paradigms have no bias. For ITD specifically, the bias only
applies when `signal_type='white'`; downstream analysis can branch on
that column.

A future signal-type-aware `spl_to_amplitude(signal_type=...)` could
correct the bias in software; deferred per Eric's preference for
documentation-now / fix-later.
